# 모듈 1 과제 보고서

- 이름: 박준명

## 문제 1

### 장비·환경·설정

PC에서 SSH로 라즈베리파이에 접속하여 OpenCR 펌웨어 빌드·업로드, 시리얼 송수신과 로그 저장을 수행했다. OpenCR은 라즈베리파이에 USB로 연결했다.

| 항목 | 실행 환경 및 설정 |
|---|---|
| 라즈베리파이 | 호스트 `pa01`, Ubuntu Server 22.04 구성, OS 출력 `22.04.5 LTS`, `aarch64` |
| 사용자·포트 | `pa01`, `dialout` 그룹 / `/dev/ttyACM0`, USB 시리얼 115200 bps |
| 제어기·모터 | OpenCR 1.0 / XM430-W210(모델 1030) 1개, ID 1 |
| 모터 통신 | 1 Mbps, Protocol 2.0 |
| 예제 | [opencr_position_p.ino](examples/opencr_position_p/opencr_position_p.ino) |
| 실행 A | OpenCR 위치 제어 Kp **0.5 (1/s)**, I·D항 0, 상대 목표각 **10°**, 명령 속도 상한 **5°/s** |

제공 예제의 ID를 12→1, 모델 검사를 XM430-W350→XM430-W210으로 수정했다. 모델 검사와 기존 정지·펌웨어 버전 검사는 유지했으며, 수정 조합의 빌드·업로드·동작은 이번 실험에서 확인했다. **이 모델과 설정이 실행 전에 과제용으로 검증됐다는 별도 근거는 확보하지 못했다.**

`READY` 출력은 확보하지 못했으나 정상 설정 응답과 실행 로그를 확보했다. 빌드·업로드 명령과 기록 범위는 [README](README.md)에 정리했다.

### 값·단위 및 측정 결과

목표값 `target_deg`, 측정값 `position_deg`, 오차 `error_deg = 목표각 − 현재각`의 단위는 **°**다. P 계산값 `p_deg_s`와 제한·정수 변환을 거쳐 모터에 전달한 제어 출력 `u_deg_s`, 측정 속도 `speed_deg_s`의 단위는 **°/s**이며, Kp는 모터 내부 게인이 아닌 OpenCR 위치 제어 게인이다.

| 경과 시간 (s) | 목표각 (°) | 현재각 (°) | 오차 (°) | P 계산값 (°/s) | 제어 출력 (°/s) |
|---|---|---|---|---|---|
| 2.000 | 10.000 | -0.088 | 10.088 | 5.044 | 4.122 |
| 3.000 | 10.000 | 3.604 | 6.396 | 3.198 | 2.748 |
| 4.001 | 10.000 | 6.152 | 3.848 | 1.924 | 1.374 |
| 5.901 | 10.000 | 8.701 | 1.299 | 0.649 | 0.000 |
| 12.402 | 10.000 | 8.701 | 1.299 | 0.649 | 0.000 |

### 결과 해석 및 정지 확인

목표가 10°로 바뀐 2.000초의 현재각 −0.088°에서 목표에 가까워져 5.901초 이후 대체로 8.701° 부근에 머물러 마지막에는 오차 1.299°가 남았고, 실제로 모터가 멈춘 것을 관찰했다. 이때 P 계산값 0.649°/s가 속도 명령 1단위(0.229 rpm × 6 = 1.374°/s)의 절반보다 작아 정수 변환에서 0으로 반올림되므로, 목표 도달 전에 출력이 0이 된 것으로 해석한다.

이후 `x`를 입력해 `STOP: user` 응답을 받았고 실제 정지 상태를 확인했다. 코드상 목표 속도 0·토크 해제 호출이 성공한 응답이며, 토크 해제 자체를 별도 물리 측정하지는 않았다.

## 문제 2

[실행 A](results/실행A.log)의 목표 변경 직후·이동 중·마지막 측정 시점을 비교했다.

| 시점 | 경과 시간 (s) | 목표각 (°) | 현재각 (°) | 오차 = 목표각 − 현재각 (°) |
|---|---|---|---|---|
| 초기 | 2.000 | 10.000 | -0.088 | 10.088 |
| 중간 | 4.001 | 10.000 | 6.152 | 3.848 |
| 마지막 | 12.402 | 10.000 | 8.701 | 1.299 |

오차 크기는 10.088°→3.848°→1.299°로 감소했으나 0이 되지 않았다. 마지막에는 문제 1에서 설명한 속도 명령의 정수 변환으로 출력이 0이 됐다.

위치는 모터 내부의 비접촉 절대 엔코더(12비트, 4096 pulse/rev)로 측정한다([공식 사양](https://emanual.robotis.com/docs/en/dxl/x/xm430-w210/#specifications)). 피드백 경로는 **엔코더 → 다이나믹셀 내부 제어기·Present Position(132) → DYNAMIXEL Protocol 2.0 응답 → OpenCR DXL 포트·Serial3 → 위치 오차 계산**이다. 예제는 현재 위치 tick에서 실행 시작 tick을 빼고 `360/4096`을 곱해 상대각을 구하며, 오차로 계산한 속도를 Goal Velocity로 돌려보낸다.

목표가 +30°이고 현재각이 +35°이면 오차는 **−5°**다. 양의 Kp에서 P 출력은 음수가 되므로, 각도를 줄이는 방향으로 보정한다(실제 시계·반시계 방향은 장비의 방향 설정에 따른다).

## 문제 3

Kp만 0.5에서 1.0으로 바꾼 [실행 B](results/실행B.log)를 [실행 A](results/실행A.log)와 비교했다. 두 값의 과제용 사전 검증 근거는 없으며, 이번 장비에서 실제 측정한 결과다.

| 조건 | 실행 A | 실행 B |
|---|---|---|
| OpenCR 위치 Kp (1/s) | 0.5 | 1.0 |
| 상대 목표각 / 명령 속도 상한 | 10° / 5°/s | 10° / 5°/s |
| 제어 요청 / 로그 주기 | 10 ms / 100 ms | 동일 소스 설정 |
| 기록된 제어 간격 | 10.000~10.003 ms | 10.000~10.004 ms |
| 기록 범위 / 목표 변경 후 행 수 | 0.200~12.402초 / 105행 | 0.100~9.200초 / 73행 |
| 정지 응답 | `STOP: user`, 실제 정지 확인 | `STOP: user`, 실제 정지 확인 대기 |

축에는 바퀴·링크·추 같은 외부 부하를 연결하지 않고 모터만 회전시켰다. A·B의 물리적 시작 각도와 이동 여유를 일치시켰다는 기록은 없으며, B의 실제 정지 여부는 로그 응답 외에 별도 확인을 기다리고 있다. 예제는 매 실행 시 현재 위치를 상대각 0°로 정하므로, 로그의 0°만으로 물리적 시작 자세가 같았다고 판단할 수 없다. 따라서 아래 결과를 Kp만의 영향으로 확정하지 않는다.

동일 경과 시간의 비교를 위해 공통 기록 범위에서 가장 가까운 표본을 사용했다. A·B 시각 차이는 아래와 같이 최대 1 ms이며 보간하지 않았다.

| A / B 경과 시간 (s) | 시각 차이 (ms) | A 현재각 (°) | B 현재각 (°) | A 오차 (°) | B 오차 (°) |
|---|---|---|---|---|---|
| 3.000 / 3.000 | 0 | 3.604 | 3.867 | 6.396 | 6.133 |
| 4.001 / 4.000 | 1 | 6.152 | 7.559 | 3.848 | 2.441 |
| 6.001 / 6.000 | 1 | 8.701 | 9.316 | 1.299 | 0.684 |
| 9.001 / 9.000 | 1 | 8.701 | 9.316 | 1.299 | 0.684 |

기록 범위의 최대각은 A 8.789°, B 9.316°로 두 실행 모두 목표 10°를 초과하지 않았다.

B는 비교한 시점에서 목표에 더 가까웠으며, 약 6초 시점의 잔여 오차는 A 1.299°에 비해 B 0.684°로 작았다. 같은 오차에 대한 P 계산값이 커지는 것과 일치하지만, 두 실행 모두 명령 속도 제한과 정수 변환을 거치므로 Kp를 두 배로 해도 전 구간의 속도가 두 배가 되지는 않는다. B의 마지막 P 계산값 0.684°/s도 raw 1단위의 절반인 0.687°/s보다 작아 출력이 0이 됐다.

변경 대상은 **OpenCR의 위치 오차를 속도 명령으로 바꾸는 Kp**이며 다이나믹셀 내부 게인이 아니다. I항은 오차를 시간에 따라 누적하여 지속적인 잔여 오차를 줄이는 역할을 한다. D항은 오차의 변화 또는 측정 속도에 반응하여 급격한 움직임과 진동을 억제하는 역할을 한다. 이번 P 예제의 I·D항은 0으로 유지했다.

## 문제 4

아래는 **발제문에 주어진 가상 통신 기록의 해석**이며, 문제 1의 시리얼 실험이나 실제 micro-ROS 구현 결과가 아니다. 목표·상태의 단위는 °다.

```mermaid
flowchart LR
    PC["PC ROS2 노드"] -->|"/motor/target: 목표각"| Agent["micro-ROS Agent"]
    Agent -->|"목표 전달"| CR["OpenCR: 제어 10 ms"]
    CR -->|"Goal Velocity"| DXL["다이나믹셀"]
    DXL -->|"엔코더 위치 응답"| CR
    CR -->|"/motor/state: 현재각, 100 ms"| Agent
    Agent -->|"상태 전달"| PC
```

PC 노드는 `/motor/target`을 발행하고 `/motor/state`를 구독한다. OpenCR의 micro-ROS 노드는 목표를 구독하여 제어에 사용하고 모터 위치를 읽어 상태를 발행하며, Agent는 ROS2와 OpenCR 사이의 통신을 중계한다. 가상 기록에서 PC가 보낸 30° 목표에 대해 수신 상태가 2°→12°→22°→29°로 증가하므로 목표에 가까워진 것으로 해석한다.

상태 발행 한 주기 동안 제어 계산은 **100 ms ÷ 10 ms = 10회** 수행된다. 상태 전달보다 빠른 제어를 OpenCR에서 수행하므로 PC 수신 주기를 제어 주기로 혼동하지 않는다.

통신 단절 정책으로 목표와 별도의 주기적 생존 신호를 사용하고, 마지막 유효 신호 후 정해진 제한 시간(설계 예: 500 ms)을 넘으면 OpenCR이 오래된 목표를 무효화하고 속도 0을 명령하도록 제안한다. 고정된 목표를 매번 다시 보내지 않아도 생존 여부를 확인할 수 있고, 연결 복구 후에는 새 목표·명시적 재시작 전까지 정지 상태를 유지해 오래된 명령의 재실행을 막는다. 실제 제한 시간과 정지 후 토크 유지 여부는 지연·부하·낙하 위험을 고려해 정해야 하며, 이 정책은 이번 예제에 구현하거나 시험하지 않았다.
